# 第四周分阶段开发提示词

下面保留课程各阶段可直接粘贴到 opencode 的提示词。本次实际由 Codex 在本机完成开发，未使用 opencode。

## 阶段一：一次性对话

你是一名帮助 Python 初学者完成课堂练习的开发助手。请在当前 LLM 总目录下的 Agent/Practice01 开发最简单的命令行大模型对话程序。
只实现一次用户输入、一次模型回答，非流式输出。将服务基础地址、API Key、模型名放在脚本旁的 config.ini 中，不在代码中写密钥。
服务使用 Chat Completions 兼容接口。使用 Python 标准库，避免安装额外依赖。尽量简单，不创建框架、数据库、网页、工具调用、抽象类或复杂分层。
提供不含真实密钥的 config.example.ini，在仓库根目录的 .gitignore 中加入 config.ini。先检查现有文件，再实现并验证本阶段功能。

## 阶段二：打字机式流式输出

请基于现有 chat.py 做最小改动，使 AI 回复随接口返回的文本分片立即显示，使用真正的流式请求和 flush，不用 sleep 模拟打字。
通过 config.ini 的 stream = true/false 切换流式和非流式，以便对比。正确忽略不包含正文的分片并处理流结束。
仍然只进行一次问答，不要添加聊天历史或其他功能。验证普通模式和流式模式。

## 阶段三：仅添加无限循环

请只修改 chat.py，把现有用户输入和问答代码直接放到 while True 无限循环中，让用户可以不断输入，直到 Ctrl+C 退出。
除此以外不作任何修改。不要在这一步添加聊天历史，不要重构，不要增加功能。

## 阶段四：发送全部聊天记录

请基于现有循环对话程序做最小改动：用 messages 列表记录本次运行中所有成功的用户提问与 AI 回答。
每次请求把此前完整记录和本次用户输入一起发给模型；流式输出结束后先合并完整 AI 回答，再加入历史。
历史只放在内存，不写数据库或聊天记录文件。保留普通输出、流式输出和 Ctrl+C 退出。验证第二轮请求包含第一轮问答。

## 收尾验收

检查配置缺失、密钥无效、网络错误、流中断时的行为。失败请求不要加入历史，允许用户继续输入；不要在日志或 Git 中暴露密钥。
保持实现简单，补充本机可运行的启动方式和简短说明。用本地模拟接口验证真实 HTTP 请求、流式即时显示和多轮历史，并明确区分模拟测试与真实模型测试。
